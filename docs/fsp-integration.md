# Интеграция с ФСП

> **Статус: демонстрационная интеграция.** В MVP нет обращения к реальному реестру Федерации спортивного программирования.
> Все достижения — синтетические, поставляются фикстурой `data/fixtures/fsp-mock.json` и помечены в интерфейсе как демонстрационные
> («достижения синтетические и не подтверждены Федерацией спортивного программирования»). Договорённости с ФСП о форме API, авторизации и составе
> полей **не существуют** — контракт ниже придуман командой как разумное допущение (см. [assumptions.md](assumptions.md)).

## 1. Зачем ФСП в продукте

Достижения ФСП — **дополнительное преимущество, а не замена подтверждённой квалификации и не условие доступа**:

* кандидат без ФСП ID проходит весь основной сценарий (регистрация → профиль → тест → публикация → приглашение) — это проверяется сквозным
  сценарием 5;
* привязанный ФСП ID без истории и сбой провайдера не ломают онбординг и поиск;
* в формуле подбора ФСП даёт не более **5 из 100** баллов (`fspEvidence`) и **никогда** не обходит жёсткие условия потребности
  (подтверждённый грейд, обязательные навыки, формат, зарплатная вилка) — см. [matching.md](matching.md).

## 2. Контракт провайдера

Модель платформы (`FspAchievement`) не зависит от формата внешнего источника. За преобразование отвечает провайдер
(`apps/api/src/modules/fsp/fsp-provider.ts`):

```ts
interface FspProvider {
  readonly name: string;
  readonly isDemo: boolean;                                   // демонстрационные данные помечаются в интерфейсе
  verifyLinkCode(externalId: string, code: string): Promise<boolean>;
  fetchAchievements(externalId: string): Promise<FspAchievementRecord[]>;
}
```

`FspAchievementRecord` — внутренняя нормализованная запись: событие (`eventId`, название, дисциплина, уровень, дата), тип участия
(`INDIVIDUAL`/`TEAM`), место, роль в команде, навыки, источник и время подтверждения. Ошибки провайдера — `FspProviderError`
(`FSP_UNAVAILABLE`, `FSP_NOT_FOUND`, `FSP_BAD_RESPONSE`).

`MockFspProvider` читает фикстуру в **намеренно «внешнем» формате** (`participant_id`, `one_time_code`, `mode: OK | UNAVAILABLE`,
`results[]` с вложенным `event`), не совпадающем с моделью платформы, и преобразует её. Путь к файлу — `FSP_MOCK_DATA_PATH` либо
`data/fixtures/fsp-mock.json`. Режим выбирается переменной `FSP_PROVIDER` (в MVP допустимо только `mock`).

## 3. Привязка, синхронизация, отвязка

| Действие | Эндпоинт | Поведение |
|---|---|---|
| Состояние | `GET /candidate/fsp-link` | `NOT_LINKED`, `LINKED_WITH_HISTORY`, `LINKED_WITHOUT_HISTORY`, `SYNC_ERROR`; список достижений с признаком релевантности специализации |
| Привязка | `POST /candidate/fsp-link` `{ fspId, code }` | проверка одноразового кода провайдером, загрузка достижений; один ФСП ID — один профиль; код **одноразовый** (`FspLinkCodeRedemption`); не более 10 попыток за 15 минут на пользователя |
| Обновление | `POST /candidate/fsp-link/sync` | заменяет достижения; при ошибке провайдера состояние `SYNC_ERROR`, **последняя успешная история сохраняется** |
| Отвязка | `DELETE /candidate/fsp-link` | удаляет связь и загруженные достижения; бонус ФСП и показ истории работодателям прекращаются |

Ошибки привязки: `422 FSP_CODE_INVALID` (неверные ФСП ID или код — причина не уточняется), `409 FSP_ALREADY_LINKED`, `409 FSP_ID_TAKEN`,
`409 FSP_CODE_USED`. Кандидат может скрыть достижения ФСП от работодателей (`showFspToEmployers`), не отвязывая их.

В карточке работодателя без доступа достижения показываются **обезличенно**: дисциплина, уровень, тип участия, место, год, навыки и пометка
релевантности специализации. Название мероприятия, точная дата и роль в команде добавляются только в карточке для компании, принявшей
приглашение; набор полей в каждом режиме закреплён тестами приватности (`privacy.int-spec.ts`).

## 4. Демонстрационные данные

Фикстура содержит 51 участника: 40 сгенерированных (`FSP-SEED-001…040`, по 10 на специализацию, часть без истории) и 11 написанных вручную
(`FSP-DEMO-*`) для сценариев демонстрации. Seed привязывает часть из них к демо-кандидатам. **Свободные коды для живой привязки на показе:**

| ФСП ID | Одноразовый код | Что в истории |
|---|---|---|
| `FSP-DEMO-1005` | `640027` | 2 записи |
| `FSP-DEMO-4001` | `411950` | 1 запись |
| `FSP-DEMO-5002` | `654321` | 1 запись |
| `FSP-DEMO-5001` | `123456` | пусто (привязан без истории) |

Код одноразовый: после привязки к одному профилю тот же код другому кандидату не подойдёт. **Для повторной демонстрации пересоздайте демо-данные**
(`pnpm --filter @fsp/api db:seed:reset`) — иначе использованные коды уже заняты.
Особые случаи в seed: `fsp.error@demo.example` (состояние `SYNC_ERROR`, последняя история сохранена), `fsp.empty1@…`/`fsp.empty2@…` (привязан, истории нет),
`oleg.tikhonov@…` (есть нерелевантное достижение по робототехнике — оно не получает бонус).

## 5. Будущая реальная интеграция (не реализовано)

Это план, а не готовый функционал.

1. **Идентификация** — вход/привязка через ФСП ID по OIDC (например, Keycloak): `issuer + subject → локальный userId`, обязательное подтверждение владения
   вместо одноразового кода. Потребует согласования scopes и политики хранения идентификаторов.
2. **Достижения** — клиент API реестра ФСП вместо фикстуры: аутентификация сервис-сервис, пагинация, повторные попытки с ограничением, кэш
   и периодическая синхронизация (сейчас синхронизация по кнопке).
3. **Контракт данных** — формат событий, дисциплины, уровни и роли нужно сверить с реестром; справочник релевантности `fsp-relevance-v1`
   пересмотреть с экспертами ФСП.
4. **Правовая сторона** — основания обработки данных участников соревнований, согласие кандидата на передачу и показ достижений работодателям.

Граница замены минимальна: достаточно реализовать `FspProvider` и добавить значение в `FSP_PROVIDER`; модель данных, подбор и интерфейс не меняются.
